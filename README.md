# p2p

Защищенный одно-пиринговый чат на C++ с использованием Boost.Asio и OpenSSL.

## Функционал

- Прямое соединение двух пиров.
- Шифрование сообщений (RSA для обмена ключами, AES-GCM для сообщений).
- Подтверждение доверия при первом подключении и автоматическая проверка ключей знакомых собеседников.
- Генерация случайных никнеймов.
- Автоматическое обнаружение пиров в локальной сети через mDNS/DNS-SD.
- CLI-интерфейс с командами: подтверждение доверия, управление доверенными ключами, подключение, отключение, отправка сообщений, поиск пиров, сведения о профиле, справка.

## Быстрый старт

### Зависимости

- C++20
- [Boost](https://www.boost.org/)
- [OpenSSL](https://www.openssl.org/)
- [nlohmann/json](https://github.com/nlohmann/json)
- [CMake 3.30+](https://cmake.org/)
- [Avahi](https://avahi.org/)
- `pkg-config`

### Сборка

```sh
mkdir -p build
cd build
cmake ..
make
```

### Запуск

```sh
./p2p
```

По умолчанию используется TCP-порт `42000`. Другой порт задается через `--port`, например `./p2p --port 42001`.

Для подключения выполните:

```text
connect <host[:port]>
```

В командах `connect` и `trust` порт по умолчанию — `42000`, независимо от собственного порта. Примеры: `connect localhost`, `connect 192.168.1.10:42001`. IPv6-адреса заключаются в квадратные скобки: `[::1]` или `[::1]:42001`.

При первом подключении обе стороны подтверждают доверие командой `yes` или отклоняют его командой `no`. На ответ отводится 60 секунд. Обмениваться отпечатками вручную не требуется. Для проверки личности сверьте их через доверенный канал. После успешного подключения ключ сохраняется и проверяется автоматически.

Изменившийся ключ отклоняется. Для его обновления проверьте новый отпечаток, выполните `disconnect`, затем `trust <address[:port]> <fingerprint>`. Параметр запуска `--peer-fingerprint <отпечаток>` позволяет заранее задать ожидаемый ключ и пропустить подтверждение при совпадении, но не заменяет сохраненный ключ.

Приватный ключ (`identity.pem`) и доверенные отпечатки (`known_peers`) хранятся в `~/.config/p2p`. Доверие привязано к IP-адресу и порту собеседника. Отдельный профиль задается через `--data-dir`, например для двух пиров на одном компьютере:

```sh
./p2p --data-dir ./alice
./p2p --data-dir ./bob --port 42001
```

### Поиск пиров

Команда `discover` ищет пиры в локальной сети через mDNS/DNS-SD. Для поиска нужна запущенная служба `avahi-daemon` и разрешенный mDNS-трафик на UDP-порту `5353`. Адреса одного объявления объединяются в запись с номером. Для подключения выполните `connect <номер>`, для просмотра всех адресов — `discover <номер>`.

Поиск занимает две секунды и работает в фоне. Если Avahi недоступен, `discover` сообщает об этом, а прямое подключение через `connect` остается доступным.

### Тесты

```sh
ctest --test-dir build --output-on-failure
```

Тесты проверяют шифрование, сетевое взаимодействие и хранение ключей. Для проверок CLI и обнаружения пиров требуется Python 3. Проверка mDNS пропускается, если служба Avahi недоступна.

## Команды чата

- `yes` / `no` — подтвердить или отклонить доверие новому собеседнику
- `trust <address[:port]> <fingerprint>` — явно задать или заменить доверенный SHA-256-отпечаток собеседника
- `connect <host[:port]>` — подключиться к другому пиру, порт по умолчанию — `42000`
- `connect <номер>` — подключиться к пиру из последнего поиска
- `disconnect` — отключиться от текущего пира
- `send <message>` — отправить текстовое сообщение: Enter отправляет, Alt+Enter или Ctrl+J добавляет новую строку
- `discover` — найти объявленные пиры в локальной сети
- `discover <номер>` — показать все адреса найденного пира
- `info` — показать имя, порт, каталог профиля и собственный отпечаток
- `help` — показать справку по командам
- `quit` — выйти из программы

## Принцип работы

- Пиры устанавливают прямое TCP-соединение.
- Стороны обмениваются открытыми RSA-ключами. Отпечатки проверяются по сохраненным записям или подтверждаются пользователем при первом подключении.
- Каждая сторона передает случайный секрет, зашифрованный с помощью RSA-OAEP. Из обоих секретов вычисляется общий сеансовый ключ AES-256.
- Зашифрованный обмен никнеймами подтверждает владение приватными ключами перед открытием чата.
- Сообщения шифруются с помощью AES-GCM и принимаются только после проверки целостности.
